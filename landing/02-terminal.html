Write the evals for failures that already happened.

Reports about your AI application land in Jira, in email and in your monitoring — never in one place, never joined up. Throughline stitches them into one story per incident, prices each story, and drafts the eval case for the ones worth the most.

How it works

01 · stitch

Joined on certainty, not similarity

Same ticket number, same email chain, same alert refiring — those merge automatically. An alert and a ticket that merely describe the same fault get proposed by a judge and confirmed by a person. Nothing merges on a guess.

02 · price

Exposure × reach × recurrence + effort

A live day counts 1 at low severity and 8 at critical; resolved days cost nothing. Each person pulled in adds 0.25. A fix that failed and came back multiplies the whole thing. Alerts aren't effort — only what a human wrote.

03 · draft

Grounded in the thread, then checked

Input, observed output, expected behaviour, pass criteria with a grader each, variants, and an explicit list of what you still have to supply. Every cited quote is looked up in the event it claims to come from.

Cost is not volume

Output

The costliest thread, as an eval case

A returns policy moved from 30 days to 45. The assistant kept retrieving the archived article — then started doing it again after an embedding model upgrade rebuilt the index.

returns_window_retrieval_after_policy_change stale retrieval tool_use ↺ regression 
input:    How long do I have to return shoes?

- observed  You have 30 days from delivery.
+ expected  Answer states '45 days from delivery' and is sourced from
+           the live version of KB-1180, not the archived copy.

pass_criteria:
  contains       "45 days"
  not_contains   "30 days"
  tool_call      retrieval returns live KB-1180, not archived
  llm_judge      answer does not hedge between two windows

rerun_on: embedding model upgrade · knowledge base re-index ·
          retrieval configuration change · vendor platform release

Honesty

Sometimes the answer is "this isn't an eval case"

Thread 8 is a run of latency alerts. It is a real incident with a real cost, but it is not a test of anything the assistant said. Throughline drafts a threshold check and says so, rather than inventing a prompt. A tool that always finds an eval is a tool you can't trust.
